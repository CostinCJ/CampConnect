# Firestore & Storage Schema

Compiled from `firestore.rules`, `storage.rules`, and each feature's `domain/` model classes
(`lib/features/*/domain/*.dart`) plus the Cloud Functions handlers in `functions/lib/` and
`functions/index.js` — treat those files as the source of truth if this document ever drifts
from them.

## Firestore collections

| Path | Written by | Key fields | Notes |
|---|---|---|---|
| `users/{uid}` | server-only create (`registerGuide`/`claimCampCode`); `joinOrganization` sets `orgId`, `removeMember` clears `orgId`/`campId`; client may update only the `campId` field on their own doc | `role` ('guide'\|'kid'), `email?`, `displayName`, `campId?`, `team?`, `orgId?`, `createdAt` | A guide switching `campId` must target a camp in their own org (enforced in rules); kids never write their own profile. |
| `organizations/{orgId}` | `registerGuide` / `rotateInviteCode` (owner-only) callables; the owner may update `codePrefix` and `logoUrl` directly | `name`, `ownerUid`, `inviteCode`, `codePrefix?`, `logoUrl?`, `attestedAt`, `attestedBy`, `organiserTermsVersion` | Readable only by guides of that org. Client writes denied except the owner's field-scoped update: `codePrefix` 2-8 chars `[A-Z0-9]`, `logoUrl` either `''` or a Firebase Storage download URL for this org's own `logo.jpg` (rules `isOwnLogoUrl`). `attested*`/`organiserTermsVersion` record the owner's controller attestation at creation (`docs/organiser-terms.md`); orgs created before 2026-09-30 lack them. `rotateInviteCode` replaces `inviteCode`. Kids read the logo URL via the `getOrganizationLogoUrl` callable. |
| `organizations/{orgId}/members/{uid}` | `registerGuide` (owner on creation, guide on join) / `joinOrganization` (org-less guide re-joins by code) / `removeMember` (owner removes a guide) / `deleteMyAccount` (removes non-owner membership) | `role` ('owner'\|'guide'), `displayName`, `joinedAt?` | Client writes denied. `joinedAt` is absent on memberships created before it was introduced. `removeMember` first strips the org from the ex-member's custom claims and revokes their refresh tokens, then clears `orgId`/`campId` on their `users/{uid}` doc, and deletes this membership doc last (so a failed call can be retried). Their current ID token keeps working until it expires (≤ 1h) unless the client checks revocation, but no new token can carry the org. |
| `organizations/{orgId}/locations/{locationId}` | org-scoped guides (client, via `location_form_screen.dart`) | `name`, `latitude`, `longitude`, `description`, `category`, `photoUrl?`, `knowledgeBase` (`description`/`facts`/`funFact`), `createdBy`, `timestamp` | Master map locations, readable by any guide or kid of the org. |
| `organizations/{orgId}/announcementTemplates/{templateId}` | org-scoped guides (client, via `announcement_templates_repository.dart`); auto-seeded with 8 built-in defaults the first time an org has none | `titles` (map: languageCode -> title), `bodies` (map: languageCode -> body), `order` | Guide-only (rules deny kid read); reusable prewritten announcements a guide can send with one tap, shared across all the org's camps like master locations. Not pushed themselves — sending one creates a normal `camps/{campId}/announcements/{id}` doc. |
| `camps/{campId}` | org-scoped guides (create/update); deletion only via the `deleteCamp` callable or `cleanupExpiredCamps` (rules deny client deletes); read by camp members or org guides | `name`, `startDate`, `endDate`, `teams` (list of team names used at creation), `createdBy`, `orgId`, `language`, `tvCode?` | `language` drives the Cloud Functions notification strings ('ro'/'hu', default 'ro'). Note: this `teams` field is a static snapshot of names captured at creation — distinct from the live, mutable `camps/{campId}/teams/{teamId}` subcollection below. `tvCode` is a guide-generated 6-char code (`camp_repository.dart`'s `generateUniqueTvCode`, unique within the org), created on demand from the points management screen; the public `tvLeaderboard` HTTP function looks up a camp by `tvCode` for the unauthenticated TV display (`docs/tv/index.html`, served via GitHub Pages), returning only team name/color/points — never personal data. |
| `camps/{campId}/teams/{teamId}` | org-scoped guides | `name`, `colorHex`, `points` | The live per-team docs (points change over time) — not the same as the `teams` name list on the parent `camps/{campId}` doc. |
| `camps/{campId}/announcements/{id}` | org-scoped guides | `title`, `body`, `type` ('announcement'\|'schedule'\|'prompt'), `pinned`, `createdBy`, `createdByName`, `timestamp`, plus `scheduledDate?`/`startTime?`/`endTime?` for schedule entries | Triggers `onAnnouncementCreated` (skips FCM for `type: 'schedule'`). `prompt` is a question-of-the-day; kids answer it into their device-local journal (nothing is written back here). |
| `camps/{campId}/emergencyAlerts/{id}` | org-scoped guides | `message`, `senderId`, `senderName`, `acknowledgedBy` (list), `timestamp`, `type` (e.g. 'missingChild', 'medical', 'weather', 'gather', 'custom'), `latitude?`/`longitude?` | Create binds `senderId` to the caller. Updates are limited to a guide adding their **own** uid to `acknowledgedBy`, or the sender adding `latitude`/`longitude` (the app sends first and attaches the precise GPS fix afterwards). Coordinates are **precise** personal data of the sending guide; never included in the push. Triggers `onEmergencyAlertCreated` (retried on failure for up to 10 minutes). |
| `camps/{campId}/pointsHistory/{id}` | org-scoped guides | `team`, `amount`, `reason`, `addedBy`, `timestamp`, `teamName`, `teamColorHex` | Triggers `onPointsChanged` (points + rank-change notifications). |
| `camps/{campId}/sessionLocations/{id}` | org-scoped guides | `masterLocationId`, `photoUrl?`, `addedBy`, `visitedAt` | Per-session copy of a visited master location, with its own group photo. |
| `codes/{code}` (top-level) | `registerGuide`/`claimCampCode` callables (create/mark-used); org-scoped guides can create/read/list/update/delete their own org's codes directly | `campId`, `orgId`, `team`, `displayName`, `used`, `usedBy?`, `createdBy` | Doc ID is the code itself (`CAMP-XXXX`). Despite the `codesSubcollection` constant name in `app_constants.dart`, this is a **top-level** collection, not nested under `camps/{campId}` — confirmed by both `firestore.rules` (`match /codes/{code}`) and `camp_repository.dart`/`claimCampCode.js`, which reference `codes/{code}` directly. |
| `rateLimits/{key}` | Cloud Functions only (`registerGuide`/`claimCampCode` via `rateLimiter.js`; `tvLeaderboard` via its own limiter) | `count`, `windowStart` | Never client-readable/writable; the Admin SDK bypasses rules, so the explicit deny in `firestore.rules` is defense-in-depth. Keys: `registerGuide:<ipHash>`, `claimCampCode:<uid>`, `claimCampCode:ip:<ipHash>`, `tvLeaderboard:<ipHash>`, where `<ipHash>` is a truncated SHA-256 of the last `X-Forwarded-For` hop (`functions/lib/clientIp.js`), so raw IPs are never stored. Purged by `cleanupExpiredCamps` once older than the one-hour window; a TTL policy on `windowStart` is a recommended backstop (`docs/operations.md`). |
| `config/registration` | **manual only** (Firebase console / Admin SDK); clients denied by rules | `orgCreationCode` (string) | **Required for creating any organisation.** `registerGuide` compares the supplied setup code against it (case/space-insensitive) and fails closed: if this doc or field is missing, every org creation fails with `invalid-org-creation-code`. Provision it in every project (prod and dev) with a long random value, and hand the code out personally to new organisers. Do **not** delete `config/` during clean-ups. Other `config/*` docs are legacy (a pre-multi-org global `guideInviteCode`) and unused. |

Notes on collections that are **not** in Firestore: `JournalEntry` (`lib/features/journal/domain/journal_entry.dart`)
and `AppSettings` (`lib/features/settings/domain/app_settings.dart`) have no `fromFirestore`/Firestore
imports — journal entries and app settings are stored locally on-device only (journal photos are local
file paths, not Storage references).

**Deletion cascade** (`functions/lib/deleteCampCascade.js`, shared by `deleteCamp`,
`cleanupExpiredCamps` and `deleteMyAccount`): Storage first (`organizations/{orgId}/sessionPhotos/{campId}/`
and legacy `camps/{campId}/`), then `recursiveDelete` of the camp, its top-level `codes`, then
`users` with `campId == campId`: **kid** profiles are deleted, **guide** profiles only have `campId`
cleared. The owner cascade in `deleteMyAccount` also deletes everything under
`organizations/{orgId}/` in Storage and the org doc tree.

## Cloud Storage paths

| Path | Written by | Notes |
|---|---|---|
| `organizations/{orgId}/locations/{locationId}/photo.jpg` | org-scoped guides (`location_form_screen.dart`) | Max 10 MB, `image/*` content-type enforced in `storage.rules` (create/update only — deletes are allowed for the org's guides without those checks, since `request.resource` is null on delete). Deleted client-side when a guide deletes the location (`master_locations_screen.dart`), and alongside the org on `deleteMyAccount`'s owner-cascade. Readable by any guide or kid of the org. |
| `organizations/{orgId}/sessionPhotos/{campId}/{sessionLocId}/group_photo.jpg` | org-scoped guides (`add_session_location_screen.dart`) — current upload path | Max 10 MB, `image/*`. **May contain images of children.** Readable by a guide of the org or a kid whose profile has this `orgId` **and** this `campId`. Uploaded with `Cache-Control: private`. Deleted by the camp cascade (prefix `organizations/{orgId}/sessionPhotos/{campId}/`) and the owner cascade. |
| `organizations/{orgId}/logo.jpg` | org-scoped guides (`organization_screen.dart`) | Max 10 MB, `image/*`. Readable by any guide or kid of the org (journal PDF branding). Deleted by "Remove logo" and by the owner cascade (prefix `organizations/{orgId}/`). |
| `camps/{campId}/sessionLocations/{sessionLocId}/group_photo.jpg` | **legacy**, no longer written | Photos uploaded before the org-scoped path. Read/delete only (no create/update). Readable by a guide of the camp's org or a member of that camp. Deleted by the camp cascade (prefix `camps/{campId}/`). |
